# AI Development Standards

**「複数のリポジトリを一人で継続的に開発するときに、AIと人間の判断・実装・UI/UXのブレを減らす」** ための Opinionated な開発スタンダードです。

本リポジトリは、あらゆる技術スタックに対応する汎用的なガイドラインではなく、**Djangoを中心としたWebアプリケーションを、AI支援で効率的・一貫して開発するため**の強いデフォルトを提供します。

## 構成と役割

このリポジトリは「どう作るべきか（判断の再利用）」を定義するものであり、UIコンポーネントやプロジェクト雛形などの実装コードは含みません。

| ディレクトリ | 役割 | 内容 |
|---|---|---|
| `ai/` | **AI エージェント向けルーター** | `ONBOARDING.md`。最初に読み、必要なStandardだけへ進む |
| `standards/governance/` | **人・AIはどう行動するか** | AI利用、Git運用、逸脱、標準追加の考え方 |
| `standards/architecture/` | **システムをどう作るか** | Django/PostgreSQL/React Islands、認証・認可、API、ログ等 |
| `standards/application-ui/` | **画面構造・操作の一貫性** | UI原則、Layouts、フォーム・エラー表現等 |
| `decisions/` | **ADR** | なぜ現在のStandardになったのかという重要な判断の背景 |

## Core Standard と Optional Standard

Standardは、肥大化と不要なコンテキスト読み込みを防ぐため2層に分けます。

- **Core Standard**: 対象プロジェクトの大半に適用され、長期間変わりにくい原則。各領域の `README.md` に置き、短く保つ。
- **Optional Standard**: 特定機能を実装するときだけ適用する詳細仕様。各領域の `optional/` 配下に置き、必要な場合のみ読む。

Optional Standardは詳細に規定して構いません。重要なのは、必要のないプロジェクトやタスクにその詳細を読み込ませないことです。

新しいルールを追加するときは、まず「Coreに必要か」「Optionalか」「StandardではなくRecommendation・実装・プロジェクト固有判断ではないか」を判断します。背景は [ADR-0004](decisions/adr-0004-core-and-optional-standards.md) を参照してください。

## 基本原則

1. **AIファースト・ルーター**: `ai/ONBOARDING.md` を起点に、タスクに必要なStandardだけを読む。
2. **Standardからの逸脱は許容する**: Standardは強いデフォルト。重要な逸脱のみ、プロジェクト側のADR等に理由を残す。
3. **実装との分離**: UIコンポーネント、ライブラリのラッパー、プロジェクト雛形などの実装コードは別リポジトリまたは各プロジェクトで管理する。
4. **繰り返しが確認されるまで増やさない**: 「将来使うかもしれない」だけではStandardや共通実装を追加しない。

## Standard追加の目安

次の問いに十分答えられない場合は、Standard化しません。

- 複数プロジェクトで同じ判断を繰り返しているか
- 統一しないことで実際に運用・UX・保守上の問題が起きるか
- AIへ同じ説明を繰り返すコストがあるか
- 長期間変わりにくい内容か

具体的なライブラリ選定だけならRecommendation、実装の再利用ならShared UI等、単一プロジェクト固有ならそのプロジェクト側に置きます。

## メンテナンスツール

本リポジトリ自体のメンテナンス用に最小限のツールのみを用意します。プラットフォーム化を防ぐため、独自の大規模な検証・生成基盤は構築しません。

```bash
just check-docs
```
