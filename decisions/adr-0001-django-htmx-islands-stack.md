# ADR-0001: 標準スタックを Django + React Islands + htmx とする

**ステータス**: 非推奨（[ADR-0002](adr-0002-frontend-technology-boundary.md) で技術境界を再定義）

## コンテキスト
社内アプリを多数開発するにあたり、プロジェクトごとにスタックがばらつくと AI エージェントの学習・資産の共有ができない。
先行プロジェクトでの運用結果を踏まえ、小〜中規模の社内アプリに最適な技術スタックを決定する必要があった。

## 決定
新規プロジェクトの標準スタックを以下とする:

- **バックエンド**: Django（SSR ファースト・ビューは HTML を返す）
- **API**: 必要な場合のみ Django Ninja（React Island のデータ取得・外部連携用）
- **フロントエンド**: htmx（部分更新）+ React Islands（複雑な UI のみ）
- **CSS**: Tailwind CSS 等のユーティリティファーストCSS
- **DB**: PostgreSQL（全環境共通）

## 理由
- **フル SPA（React + REST API）**: 社内アプリには過剰。フォーム・バリデーション・権限をフロントに複製することになり、AI が生成するコード量と不整合リスクが倍増するため不採用。
- **Django テンプレートのみ**: リッチな UI（チャート・ウィザード・日付範囲選択など）の実装が苦しい。
- **htmx + Islands のハイブリッド**: ルーティング・フォーム・権限はサーバに一本化したまま、必要な箇所だけ React 化できる。AIエージェントにとっても複雑性が限定的になる。
- **PostgreSQL 統一**: 開発用 SQLite と本番用 PostgreSQL の間で、機能差異による乖離が発生するのを防ぐため。

## 結果
- 良い点: AI エージェント・UI 部品・雛形を全プロジェクトで共有できる。フロントエンドの複雑性が最小限に抑えられる。
- 注意点: React の適用範囲を「Islands」に限定する規律が必要。
